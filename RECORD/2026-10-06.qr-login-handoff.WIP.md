# QR login handoff from a phone

- **Status:** WIP
- **Started:** 2026-10-06
- **Roadmap:** ROADMAP/2026-09-17/09-nice-to-haves.md (`qr`)

## 2026-10-06 15:10 — Started, ahead of the controller UI

Tried on the mini PC from the Steam tile: the paste prompt is unusable from the
sofa, so `qr` was pulled forward rather than waiting for `grid`. It lives in the
terminal for now; the controller UI can draw the same URL later.

- `core::handoff` binds a `std` one-page server to the LAN address only (found by
  asking the routing table, never `0.0.0.0`), on a 128-bit random path, for ten
  minutes. GET shows a link to the GOG authorization URL and a paste form; POST
  hands the pasted address to the same `Session::log_in` the terminal uses, so the
  exchange stays in the binary. A failed exchange is shown on the phone, which can
  retry; the first success ends it. Nothing logs the body or the code.
- `gamestore login` prints the QR (half-block Unicode, colours inverted for a dark
  terminal) above the old prompt. The terminal paste still works and races the
  phone; `--no-qr` or `[login] qr = false` restores the old behaviour.
- The port is fixed (`[login] qr_port`, default 8731) instead of ephemeral, so a
  firewall can be opened once. On this machine ufw is active and needed
  `ufw allow from 192.168.0.0/16 to any port 8731 proto tcp`.

Checked: the server answers on the LAN address, a wrong path is a 404, a bad paste
shows GOG's error on the page. Not yet checked: a real GOG login end to end from a
phone.

Open, from the roadmap note: GOG renders its login page for an unregistered
`redirect_uri` too, so whether it rejects one only shows up after logging in. If it
accepts `http://<lan-ip>:8731/<path>`, the paste step on the phone disappears.

## 2026-10-06 15:40 — Second QR, straight to GOG

The first try from a phone failed: ufw dropped the connection to 8731
(`[UFW BLOCK] … DPT=8731` in the kernel log) because the rule above had not been
added yet. That is the failure this flow will meet most often, so the LAN page is
no longer the only option on screen.

`gamestore login` now prints two QR codes side by side (stacked when the terminal
is narrower than both): the LAN page as before, and the GOG authorization URL
itself. The second needs no port, no firewall and nothing on the LAN; the phone
logs in and the code it lands on is typed into the terminal, which already accepts
a bare code. Width comes from `COLUMNS`, then `stty size` on `/dev/tty`, then an
assumed 120.
