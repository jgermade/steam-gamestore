## 2026-09-17 08:40 — The library, cached, with the response shapes still assumed

`core::catalog` fetches what the account owns, caches it, and answers the questions
the grid will ask of it.

- **`ProductId`** — the identifier `02-core.md` asks for, the one `state`, `art` and
  the Ludusavi mapping all key on. GOG's product id, kept as a newtype over a
  string. The string is because the id is numeric today and that is not a promise;
  the newtype is because the Steam appid is *also* a number for the same game, and
  the two are not interchangeable — one is owned by GOG, the other derived by us.
  Letting them both be `u32` is how they eventually get swapped at a call site.
- **`Catalog`** — `fetched_at` plus games sorted by title, with `get`, `len` and
  `search`. Sorting happens here rather than in the UI so the grid order does not
  depend on the order GOG paginates in.
- **`fetch`** — follows `totalPages`, sends the access token as a bearer on every
  page, de-duplicates by id.
- **`load` / `save` / `load_or_fetch`** — the cache under `Paths::cache_dir`, so
  browsing does not need the network.

`gamestore library [--refresh] [--search X]` prints it.

### This task stays WIP, and this is the reason

**Nothing here has been checked against GOG.** The proxy denies `embed.gog.com`
from this session exactly as it denies `auth.gog.com`, so every field name in this
file — `products`, `totalPages`, `worksOn`, `mediaType=1` — is taken from what other
open-source clients read, not from a response anybody saw. The code is complete and
the tests are real, but they test it against fixtures this repository invented, and
a fixture cannot disagree with the assumption that produced it.

So `cat` is not closeable until the mini PC run, and the honest description of its
state is "written, unverified", the same state `auth` was in. What that run should
settle:

1. Whether `getFilteredProducts` still paginates with `totalPages`, and whether
   `mediaType=1` is still the games filter.
2. Whether `worksOn` carries the keys assumed here.
3. Whether the product id is a number or a string in the current response — both
   are accepted, so this one cannot break, but it is worth knowing which.
4. What a library with DLC, bundles and pre-orders in it actually returns. The
   fixtures have none of those, and they are the rows most likely to be malformed
   from this code's point of view.

The tests are written so that replacing the fixtures with real bodies is the whole
job: the constants at the top of the test module are the only place a shape is
asserted.

### Where the parsing is forgiving, and where it is not

Being strict about an unofficial API means breaking on GOG's next deployment;
being lax means silently showing a wrong library. The split taken here:

- **Unknown fields are ignored.** No `deny_unknown_fields`, because GOG adding a
  field is not an error on our side. There is a test with an invented field and an
  invented platform.
- **A product that cannot be read is skipped, not fatal.** One malformed row must
  not cost the user the other four hundred games. It is the DLC-and-bundles case
  above that makes this likely rather than theoretical.
- **A response that is not the expected shape at all fails loudly**, and the message
  says GOG may have changed it, because that is the real diagnosis and the
  alternative is an empty library that looks like an empty account.
- **A non-2xx status fails with GOG's own first line included** — a 401 on a stale
  token should read as a 401, not as "you own nothing".
- **A cache that cannot be parsed is treated as absent.** It is derived data;
  refusing to start over a throwaway file would be the wrong trade.

### On the bearer token

`HttpClient` grew `get_authorized`, and the trait is arranged so that the
*authorized* call is the one implementors must provide while plain `get` defaults
to it. The other way round — `get` required, `get_authorized` defaulting to it —
would let a client silently drop the `Authorization` header, and the symptom of
that is an empty library rather than an error. There is a test asserting the token
reaches every page for the same reason.

### Verification

113 tests in the workspace; 14 are new. Beyond the parsing rules above: pagination
following `totalPages`, sorting not depending on page order, a game repeated across
pages appearing once, `load_or_fetch` not calling GOG a second time (the fake runs
out of pages if it does), and search being a case-insensitive substring.

By hand, with a cache seeded by hand since the network is denied: `gamestore
library` listing three games including a non-ASCII title, and `--search got`
narrowing to one.
