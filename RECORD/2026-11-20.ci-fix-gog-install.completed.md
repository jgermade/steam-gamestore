# Fix CI on the gog-install branch (PR #6)

- **Status:** completed
- **Started:** 2026-11-20

## 2026-11-20 — Linux and Windows check jobs

Both `check` jobs of `build.yml` failed on PR #6 (run 43064350487).

- **linux:** `gilrs`, the controller input the new `ui` crate uses, builds
  `libudev-sys`, which needs the system `libudev` through pkg-config. The
  workflow now installs `libudev-dev` on Linux runners, in the `check` and the
  `package` jobs.
- **windows:** `core::details::storage` imported `std::os::unix::fs::MetadataExt`
  unconditionally, so `gamestore-core` did not compile for
  `x86_64-pc-windows-msvc`. `storage` and `filesystem` (which relies on GNU
  `df` flags) are now `#[cfg(target_os = "linux")]`, as is their test; their
  only caller is the Linux-only `ui` crate.
- Also on Windows, once the above compiled: the artwork test
  `saving_replaces_other_formats_and_writes_a_shared_dir_once` calls
  `std::os::unix::fs::symlink` and would have failed `clippy --all-targets`
  next. It is now `#[cfg(unix)]`, like the other Unix-only tests in `core`.

Verified locally on Linux: `cargo fmt --check`, `cargo clippy --workspace
--all-targets -- -D warnings` and `cargo test --workspace` pass. The Windows
target could not be fully checked here (a C dependency needs MSVC's
`lib.exe`); the next CI run is the check.

## 2026-11-20 — Correction: Windows still failed, more Unix-only code

The first fix was not enough: run 44804327453 passed on Linux but failed on
Windows, and the note above that Windows "could not be fully checked here" is
now superseded: `cargo clippy --workspace --all-targets --target
x86_64-pc-windows-gnu -- -D warnings` (mingw) reproduces the Windows job's
`cfg` surface locally, and it found:

- `gamestore-platform-linux` uses Unix APIs in its library (`process_group`,
  `PermissionsExt` in `inno.rs` and `native.rs`), not only in tests. It is
  Linux-only by design, so the whole crate is now `#![cfg(target_os =
  "linux")]` and builds empty elsewhere. `gamestore-ui`, built on it, gets the
  same gate. `cli` already depended on both only on Linux.
- `cli/src/main.rs`: the `Command::SteamInstall` match arm lacked the
  `#[cfg(target_os = "linux")]` its variant and sibling arms have.
- `core/src/artwork.rs`: the `Images` test helper, used only by the now
  Unix-only symlink test, was dead code on Windows; it is `#[cfg(unix)]` too.

Windows (gnu) clippy and build pass locally, and so do Linux fmt, clippy and
tests. The MSVC target itself is confirmed by CI.
