## 2026-10-06 18:45 — First version, used from the sofa

`gamestore ui` (crate `ui`): eframe 0.36 fullscreen, gilrs, our own on-screen
keyboard, GOG vertical covers cached under `<cache>/covers`, registry badges,
progress on the cover, install through `platform_linux::install` with Steam writes
deferred, and Start to restart Steam. The gamestore tile now runs `ui`, without a
terminal, in all three accounts. Text follows `LANG` (Steam's is `es_ES.UTF-8`).

The owner installed Freedom Planet, Moto Racer and Re-Volt from it on the TV; the
queued tiles were written by the `steam-launcher` drop-in when Steam restarted
(`journalctl --user -u steam-launcher`: "added to Steam: Re-Volt"). So the spike's
three questions are answered: it renders under gamescope with no desktop session,
the controller drives it, and the deferred-write design works end to end.

What the installs showed:

1. **Moto Racer closed by itself.** GOG's primary play task, `MotoRacer.exe`, is
   "Moto Racer Launcher for GOG.com": a .NET 4.8 settings window (run by Mono under
   Proton) that throws `Win32Exception: invalid window handle` and exits. The game
   is `game.EXE`, and the launcher passes it the `Params=` line of
   `motoracer.ini`. `core::fixes` now holds per-game corrections of this kind, with
   Moto Racer as the first; each entry says how it was found. The CD-audio
   `MCI_OPEN` error in `data/delphine.err` is not what closes it: `game.EXE` run
   directly stays up with it.
2. **Reinstalling must replace the old tile.** The fix changes the exe and so the
   appid. A pending tile now carries `replaces` (the registry's previous
   `steam_appid`), and writing it removes the old shortcut from every account, its
   `CompatToolMapping` entry and its artwork. Wolfenstein 3D's tile, stored with
   the pre-`resolve_case` path, was replaced the same way. The old `compatdata`
   prefixes stay behind; removing them is `uninst`'s job.
3. **Stopping Steam and writing in the gap is a race under a session.**
   `systemctl --user stop steam-launcher.service` was followed by the session
   starting it again within seconds, so a CLI install with `--restart-steam` found
   Steam running and queued instead. `--restart-steam` now queues and runs
   `systemctl --user restart` on the unit (installing the drop-in if needed), so the
   write happens in `ExecStartPre`, when Steam is certainly stopped. Stop-and-write
   remains only where there is no unit.
4. **Freedom Planet's controller does not work under Proton.** It is a Chowdren
   (Clickteam-to-C++) build using SDL2 over XInput. Not yet diagnosed. GOG has a
   native Linux build of it, which this project does not install yet.

After a restart, Steam asks which account plays ("Preguntar qué cuenta…" is on),
so every restart from the UI ends on that screen.

## 2026-10-06 19:40 — Native builds, a menu, and Moto Racer the hard way

Asked for by the owner after using the UI: prefer native Linux builds and let the
UI choose; B shows downloads instead of quitting; Start offers "restart Steam" or
"quit"; artwork for the gamestore tile. All four are in, the native path checked
with Freedom Planet's real Linux installer (its Windows build had no controller
under Proton; the native one replaces it, side by side in "<title> (Linux)").

Moto Racer took five rounds, each one a real finding:

1. Its GOG launcher is a settings window; the game is `game.EXE` (`core::fixes`).
2. Without `-fullscreen` it stops at "16 bit screen mode required"; with it, it
   still checks the desktop's depth. `assets/windows/depth16.c`, a 2 KB launcher
   built with clang and lld-link alone, switches to 16-bit colour around the game.
   The switch must name width and height too, or only the caller sees it, and it
   must be registered (`CDS_UPDATEREGISTRY`), because games and dgVoodoo restore
   the desktop mode when they re-create their display.
3. Its music is CD audio, emulated by a `winmm.dll` GOG ships next to the game.
   Wine prefers its builtin, the game fails `MCI_OPEN cdaudio "c:"` and crashes in
   its error path. Fixes can now carry Wine DLL overrides (`winmm=n,b`), given to
   Steam as `WINEDLLOVERRIDES=… %command% …`.
4. Its GOG installer writes `HKLM\Software\Wow6432Node\DelphineSoft\MotoRacer`.
   gamestore installed with a throwaway prefix and lost that. **This is general**:
   the install prefix now becomes the game's Steam prefix (`compatdata/<appid>`),
   copied when the library is on another filesystem, and a replaced tile takes its
   prefix along, saves included.
5. It is locked to 640×480. dgVoodoo2 (fetched from its GitHub release, SHA-256
   pinned, `platform_linux::tools`) renders it at 1440×1080 with 4× MSAA and 16×
   anisotropic filtering, 4:3. Its in-game 16:9 mode fails under dgVoodoo with the
   same 16-bit message for a reason not found: 16-bit modes are enumerated and the
   desktop reports 16. `DesktopBitDepth = 16` crashes dgVoodoo's DDraw.dll.

Two mistakes of mine on the way, worth not repeating: `timeout` around `proton
run` kills the script, not the game, and a forgotten `game.EXE` in the same prefix
made the next launch from Steam hang; and `pgrep -f` matches the shell running it.

## 2026-10-08: retry, artwork picker, a detail view that keeps to its space

- **Retry.** A failed install can be retried from the detail view (the failed
  build's button reads "Try again" and comes first) and from the downloads panel,
  whose rows now take focus (up/down) with A retrying the focused failure.
- **Artwork picker.** "Artwork" in the detail view lists what SteamGridDB has of
  each kind (cover, wide, background, logo; LB/RB or up/down between kinds, up to
  30 each). A puts the image into every Steam account's grid directory when the
  game has a tile, and a cover also becomes the store's own grid cover. Picks are
  remembered in `<data>/artwork/<id>.json` and installs use them before
  SteamGridDB's favourites, so a reinstall keeps them. Steam shows changed
  artwork after it restarts.
- **Detail view overlap.** The build lines were laid out without wrapping and ran
  under the screenshot column on long lines ("Windows version · Download · On
  disk"). The info is now clipped to the space left of the column, the sizes
  wrap to a second line, and the buttons wrap to a second row.
- **Slow screenshots.** The one media thread served everything in order, so a
  screenshot waited behind a details request and behind measuring an installed
  game's size (seconds on a 35 GB game). Now there is a network lane of three
  threads and a disk lane of one; details are fetched once a cover has been in
  focus for 400 ms, and the next two screenshots are fetched with the current one.
  Checked on the TV: Ghost of a Tale's detail opened with its screenshots in place.
- The UI font has ◀▶ but not ▲▼ (empty boxes in the footer), so footer arrows are
  drawn as triangles.

## 2026-10-09: the store's covers are Steam's, and the focus border moves

- A game with a Steam tile shows the tile's portrait (`<appid>p.*` in the grid
  directory) in the store's grid, so a cover picked in the artwork picker, or
  SteamGridDB's choice at install, is the same in both. Covers are asked for again
  when an install finishes. Other games keep GOG's cover.
- The focused button's border (detail view, Start menu, confirmations): a pale line
  in a breathing purple glow, with a white light running round it every 2.2 s.
  Checked on the TV across three frames.
