# SteamGridDB is in: grid covers, and artwork for the Steam tiles themselves

- **Status:** completed (decision recorded; the work lands in `art` and in a new
  Linux task)
- **Started:** 2026-09-17
- **Roadmap:** settles open question 8 in ROADMAP/2026-09-17/10-open-questions.md;

## 2026-09-17 01:00 — Decision

SteamGridDB may be used. That settles open question 8 and takes the artwork
fallback out of the nice-to-have list.

### Source order for the UI grid

1. **SteamGridDB vertical grids** (600×900) — the shape a cover grid actually
   wants.
2. **GOG's own artwork** from the catalog, for anything SteamGridDB does not have.
3. **Placeholder** with the title, last.

GOG serves logos and background images rather than portrait box art for most
titles, which is why SteamGridDB goes first rather than second: it is the
difference between a grid of covers and a grid of wide logos.

### The bigger consequence: the Steam tiles

Steam reads custom artwork for a shortcut from
`userdata/<user>/config/grid/`, which is how Boilr and the SteamGridDB managers
make non-Steam entries look native: a portrait grid, a landscape capsule, a hero
and a logo per appid. With SteamGridDB available we can fill those too — and
"indistinguishable from native Steam games" is the goal in `docs/gog-installer.md`,
so this stops being cosmetic.

This is **new work**, not part of `art`: a task next to `vdf` in the Linux phase
that writes the artwork files for the shortcuts we create, and removes them again
on uninstall. It depends on `appid`, and on a subtlety to confirm there: the
filenames use a different appid variant from the 64-bit shortcut id, which is
exactly the kind of mismatch `03-platform-linux.md` already warns about. Get it
wrong and Steam shows a blank tile.

### API key

SteamGridDB needs a key, and keys are free and per-user.

- The key is **user-supplied and optional**, in an `[art]` config section or an
  environment variable, the same shape as the GOG credentials.
- **Without a key nothing breaks**: the grid falls back to GOG artwork and
  placeholders, and the Steam tiles keep whatever Steam shows by default.
- Shipping a shared key is not the plan: one key across every install is a rate
  limit waiting to be hit, and it is not ours to distribute.

### Matching, caching, politeness

- Resolve the GOG product to a SteamGridDB game **once**, when the game enters the
  catalog, and persist the resolved id in the registry — the same rule as the
  Ludusavi title mapping, for the same reason. Manual override in config for
  titles that do not match.
- Prefer a lookup by GOG id if the API supports one, and fall back to a name search
  on the catalog title.
- Fetch on catalog refresh, never while drawing a frame. Cache under
  `Paths::cache_dir`, keyed by product id and asset kind, so the grid works
  offline.
- **Filter out adult and joke artwork by default.** The API takes `nsfw` and
  `humor` parameters; the mini PC is shared with the kids, and a default of "off"
  is the only sane one here. Overridable in config, not in the UI.
- Artwork is user-uploaded to SteamGridDB: cache it locally for our own display,
  do not redistribute it.

### Not verified from here

The session's proxy denies `api.steamgriddb.com` (403 on CONNECT), so both of these
are open until someone runs them on the mini PC:

1. Whether the API exposes a lookup by GOG id, or whether matching has to go
   through a name search.
2. Which appid variant Steam expects in the `config/grid/` filenames for a non-Steam
   shortcut.
