# A GOG game installed and played by hand, end to end

- **Status:** completed
- **Started:** 2026-10-06
- **Roadmap:** ROADMAP/2026-09-17/02-core.md (`dl`, `ver`),
  ROADMAP/2026-09-17/03-platform-linux.md (`compat`, `inno`, `wrap`), `art`, `art2`

## 2026-10-06 16:50 — What was done, and what it showed

Before writing any of the install path, it was walked by hand on the mini PC
(AMD, CachyOS, gamescope session, Steam with Proton 11.0) with Xeno Crisis
(GOG id 1955095293, 162 MiB). Every step used gamestore's own session and, where
one existed, its own code; the throwaway programs used for the Steam writes were
deleted afterwards. The game was played to completion of a session from the
controller, so this is milestone M2's shape proven once, not M2 done.

### Download — the offline installer is enough

- `api.gog.com/products/<id>?expand=downloads` lists installers per OS and
  language; each file's `downlink`, fetched with the bearer token, returns JSON with
  a CDN `downlink` and a `checksum` URL. A plain GET on the CDN URL downloads.
- `total_size` in the API is **not exact** (168 820 736 vs 169 744 608 actual). The
  `checksum` XML has the exact size, the file MD5, and an MD5 per 10 MiB chunk —
  which is everything `ver` and resume need, by range request, with no manifest.
- **This questions the critical path.** `man` + `dl` (21 days, "critical") target
  the Galaxy content-system protocol. The offline installer reached a playable game
  with an HTTP GET and an MD5. The Galaxy protocol still has real advantages
  (per-file delta updates, no installer quirks), but it does not have to precede M2.

### Install — `inno` works as written, with two corrections

- `proton run <installer> /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP-
  /DIR=Z:\…\games\<title> /LOG=Z:\…\install.log` installed silently in 7 s.
- The installer path **must be absolute**; a relative one fails with
  `err:steam:run_process Failed to create process … : 2` and exit 1, silently.
- `DISPLAY` must be set (the gamescope session's is `:0`); without it Proton exits 1
  just as silently. `Error while copying … amdxcffx64.dll` is Proton noise
  (`optional=True` in its script), not the failure.
- The game was installed **outside** the prefix, into the configured install root,
  with a throwaway prefix. The installer ran no redistributables, so nothing of
  value was left in that prefix and Steam's own prefix was fine at play time. That
  removes a chicken-and-egg: the appid (which needs the exe) does not have to exist
  before the install. Games whose installers do run redistributables will need the
  real prefix; that is a case to detect from `install.log`, not the default.
- The exe is in `goggame-<id>.info`: `playTasks[]` with `isPrimary: true`, `path`
  relative to the install dir. That is the `inno` detection step, solved.

### Steam — `compat` is right, `wrap` as designed conflicts with it

- Shortcut written with `Shortcuts::upsert` while Steam was stopped, plus a
  `CompatToolMapping` entry `"<appid>" { name "proton_11", config "", priority
  "250" }` in `config/config.vdf`. Steam logged `Mapping AppID 2907567421 to tool
  "proton_11" with priority 250`, launched through `SteamLinuxRuntime_4` and
  `proton waitforexitandrun`, and created `compatdata/2907567421` — the derived
  number. **`appid` is now verified end to end, prefix included.**
- `wrap` as designed (the tile points at a script that calls `proton run` itself)
  cannot coexist with `compat` (Steam runs the tile's target under Proton). The
  shape that keeps both, and keeps Steam's runtime, overlay and gamescope
  integration: the tile points at the game exe with the Proton mapping, and
  `LaunchOptions` is `<wrapper> %command%`, so the wrapper receives Steam's whole
  Proton command line, runs `ludusavi restore`, execs `"$@"`, and backs up after.
- Saves landed in the prefix (`AppData/LocalLow/<publisher>`), where Ludusavi
  looks.

### Artwork — keyed on the 32-bit appid, and GOG is a weak source

- Files in `userdata/<user>/config/grid/` named `<appid>p` (portrait), `<appid>`
  (wide), `<appid>_hero`, `<appid>_logo`, with the **32-bit** appid, are picked up.
  This answers the open artwork question in the verification plan.
- GOG sources, checked image by image: `gamesdb.gog.com` vertical cover is at most
  342×482 (Steam shows 600×900); its `logo` is not a transparent logo but the wide
  capsule again; the catalog's `coverHorizontal` (1600×740) is the right wide
  image. **`catalog.gog.com/v1/catalog?productId=in:<id>` ignores the filter** and
  returned another game (The Saboteur); search by title and check the id.
- SteamGridDB (`/search/autocomplete`, then `/grids` at `600x900` and
  `920x430,460x215`, `/heroes`, `/logos`, `types=static&nsfw=false&humor=false`)
  gave correct, full-size art for all three games tried, including two non-GOG
  ones. The first result is not always the best one; a person picked two of the
  twelve. `art2` is worth more than its "nice to have" placement suggests.
- The key lives in `config.toml` under `[steamgriddb] api_key`, masked by
  `gamestore config` like the GOG secret. The platform keyring was considered and
  rejected for this machine: KWallet is password-protected, not unlocked by PAM, and
  the session autologins into gamescope, so it would prompt at every boot or be no
  safer than the `0600` file.

### Multi-user — question 5 met a real household

Shortcuts were copied verbatim (same appid) into the two other Steam accounts, and
their `grid/` was made a symlink to the first account's, which is safe because
Steam only reads it. `shortcuts.vdf` itself cannot be shared that way: Steam
rewrites it on exit. Per-user saves for an emulator were solved by profile, outside
this repository; for GOG games the same need lands on Ludusavi, whose backups are
per machine user, not per Steam user.

## Proposals for the next roadmap revision

1. Put an **installer-based `dl`** (offline installer, checksum XML, resume by
   range) on the critical path to M2; move the Galaxy content system after it.
2. Rewrite `wrap` as a `%command%` wrapper in `LaunchOptions`, so `compat` and
   `wrap` stop contradicting each other.
3. Make `inno` set `DISPLAY` and use absolute paths, read `playTasks`, and keep the
   prefix throwaway unless the install log shows redistributables.
4. Move `art2` (SteamGridDB) next to `art`, with GOG only as the fallback.
5. Question 5 has a working answer to propose: install for every account, share
   `grid/`, and key Ludusavi backups by Steam account.
