## 2026-09-17 09:20 — What is on the disk, and what to do when the answer is "half"

`core::registry` records what the catalog cannot: the catalog says what the account
owns, and the disk is the only thing that knows what is installed. The badge in the
grid, `uninst` and the launch wrapper all need that second answer.

`Entry` carries exactly what `02-core.md` asks for — state, build, install path,
wrapper path, Steam appid, last successful launch — plus a failure reason and a
claim. `Registry` is a map keyed on `ProductId`, saved through `core::atomic`.

### The registry is not the catalog, and is handled the opposite way

A corrupt catalog is discarded and refetched; a corrupt registry is an **error**
that names the file and says to move it aside. The asymmetry is the point. Losing
the catalog costs one refresh. Losing the registry means gamestore no longer knows
what it installed: the games become files nobody owns, the prefixes become disk
space nobody can reclaim, and `uninst` cannot find the shortcuts it wrote. Silently
starting fresh would turn a bad parse into an orphaned installation, which is the
expensive failure, so it refuses instead. There are tests for both directions,
deliberately next to each other.

### The crash-mid-install problem

The roadmap's requirement is that a `downloading` or `installing` entry that no
process owns must be "resumable or clearable, not a permanently stuck tile". This
is the part that needed a design rather than a data structure, because a tile stuck
on "Installing" forever is exactly what a console switched off at the wall produces.

What is implemented: a transient state carries a **claim** — the pid that set it and
when. `reconcile` clears claims that are dead, moving the entry to `Failed` with a
reason the UI can offer a retry from, and returns what it reset so the caller can
say so. A claim is dead when the process is not running, *or* when it is older than
`CLAIM_MAX_AGE` (24 hours).

Two judgement calls inside that:

- **A transient state with no claim at all is treated as interrupted.** Whatever set
  it never recorded itself, and the only safe reading is that it is over.
- **Liveness is exact on Linux and optimistic elsewhere.** `/proc/<pid>` answers it
  on the target platform with no dependency. There is no equally cheap check on
  Windows, so `pid_is_alive` answers `true` there and the 24 hour age is what
  eventually clears the claim. Optimistic is the right direction to be wrong in: the
  cost is a tile that looks busy for a day, where answering "dead" wrongly would
  clobber a download that is still running. The age exists precisely so the
  optimistic answer is not the final one.

`reconcile_with` takes the liveness test as a parameter, which is what makes all of
this testable without spawning processes; `reconcile` supplies the platform one.

**This is the half of the problem that can be solved without `dl` and `inno`.** The
registry can now tell an interrupted install from a live one and offer a way out of
it, but "resumable" in the stronger sense — picking a download back up from the
chunks already on disk — belongs to `dl` and `ver`, which own the partial files.
What is here is the state machine those will drive, and the guarantee that they
cannot leave a tile stuck.

### Wired into the CLI

`gamestore library` now reconciles before it draws, prints a state column beside
each game, and says once which games were interrupted. Persisted, so the second run
does not repeat the message.

### Verification

128 tests in the workspace; 15 are new. The ones carrying the design: a claim
surviving exactly as long as its process, a stale claim clearing even when the pid
looks alive, a transient state with no claim counting as interrupted, reconciling
never touching a settled entry (asserted by comparing the whole registry before and
after), a retry clearing the previous failure so the old reason is not shown again,
and a registry written without the optional fields still loading — every one is
`#[serde(default)]`, so adding a field later does not invalidate what is on disk.

By hand: a registry seeded with an `installing` claim from pid 999999 showing as
`failed` with the message, then staying that way on the next run.

The non-Linux branch was checked with the same trick as the last two records, this
time by rewriting `target_os = "linux"` to `macos` so the fallback compiles here.
Clean, and its 14 platform-independent tests pass.
