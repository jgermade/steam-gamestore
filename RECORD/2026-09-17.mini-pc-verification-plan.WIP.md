## 2026-09-17 07:30 — Why this file exists

Six tasks have now been written in a session that can reach neither GOG nor Steam,
and each one recorded its own list of what it could not check. Those lists are
spread across five records, and between them they describe **one afternoon on the
mini PC** — not five separate errands.

This is that afternoon, assembled and ordered by dependency, so it can be worked
through top to bottom without re-reading the other records first. Every item names
the record it came from; none of it is new, and nothing here supersedes those
records. When the run happens, the results go into the individual task records —
that is where the task states live — and this file is renamed to `.completed.md`.

The ordering matters: nothing below step 1 can be done without a token, and steps 3
and 4 need Steam rather than GOG.

## Step 2 — `cat`, the library

Source: `RECORD/2026-09-17.library-catalog.WIP.md`.

Every field name in `core::catalog` is taken from what other open-source clients
read. `gamestore library --refresh` is the whole test.

- [ ] Does `getFilteredProducts` still paginate with `totalPages`, and is
      `mediaType=1` still the games filter?
- [ ] Does `worksOn` carry the keys assumed (`Windows`, `Mac`, `Linux`)?
- [ ] Is the product id a number or a string in the current response? Both are
      accepted, so this cannot break — it is worth knowing which.
- [ ] **Run it against a real library with DLC, bundles and pre-orders in it.** The
      fixtures have none of those, and they are the rows most likely to be malformed
      from this code's point of view. A product that cannot be read is skipped
      rather than fatal, so watch for a count that is quietly short rather than for
      an error.

When these are answered, replace the fixture constants at the top of
`core::catalog`'s test module with real response bodies. They are the only place a
shape is asserted, and that substitution is what closes `cat`.

## Step 3 — `appid`, against Steam itself

Source: `RECORD/2026-09-17.steam-appid.completed.md`.

The tests prove the CRC is a real CRC-32 and that the composition is
self-consistent. What no test here can prove is which string Steam feeds in and
which mask it applies. Only Steam can.

- [ ] Add a non-Steam shortcut by hand in Steam, to a known exe with a known name.
- [ ] Run `gamestore appid --exe <that path> --name <that name>`.
- [ ] Confirm the printed appid is the name of the `compatdata` directory Steam
      created. If it is not, **stop** — `vdf`, `compat`, `wrap` and `uninst` all
      inherit this number, and a mismatch does not fail loudly, it silently prepares
      a prefix Steam never launches into.
- [ ] Note whether the exe Steam stored is quoted the way `quote_exe` assumes. That
      is the most likely single cause of a mismatch.

## Step 4 — `vdf`, against a real `shortcuts.vdf`

Source: `RECORD/2026-09-17.shortcuts-vdf-writer.completed.md`.

The document the tests round-trip is one this repository constructed. It is shaped
like the real thing, which is not the same as being it.

- [ ] Take a `shortcuts.vdf` Steam actually wrote, ideally from an account with
      shortcuts added by Steam *and* by another tool, and confirm it parses and
      re-serializes **byte for byte**. That assertion already exists; it just needs
      pointing at a real file.
- [ ] Confirm `steam_users` finds every account under `userdata/`, including the
      kids'.
- [ ] Confirm the practical claim the module documentation makes: a shortcut written
      while Steam is running is discarded when Steam exits. This is the most likely
      way a first install appears to do nothing, and it decides whether detecting a
      running Steam has to move earlier than `compat` (see
      `RECORD/2026-09-17.pending-roadmap-changes.WIP.md`).
