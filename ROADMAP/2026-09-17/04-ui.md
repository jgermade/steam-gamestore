# Phase 3 — UI

**Gantt IDs:** `spike`, `grid`, `search`, `actions`, `feed` → milestone `M3`
**Window:** 2026-09-17 → 2026-12-09
**Depends on:** `cat`, `art`, `state` (for `grid`), `inno` and `uninst` (for
`actions`), `wrap` (for `feed`)

## Goal

The Steam tile opens a controller-driven UI: a grid of covers, a search box with an
on-screen keyboard, a badge per game saying whether it is installed, a progress bar
while it installs, and install/uninstall actions. The CLI stays as the headless
path — it is what makes all of this testable without a display.

Recorded in
[`RECORD/2026-09-16.controller-ui-requirement.completed.md`](../../RECORD/2026-09-16.controller-ui-requirement.completed.md),
including why the toolkit is `egui`/`eframe`, why the on-screen keyboard is ours
rather than Steam's, and why uninstall never touches saves.

## Tasks

### `spike` — Gamescope and gamepad spike (5d, scheduled first)

Deliberately at the start of the plan, in front of everything it depends on,
because three things cannot be judged from a desktop and finding out in December
would be late:

- [ ] A fullscreen `eframe` window that renders under gamescope with no desktop
      session.
- [ ] A cover grid with fake data, focus navigation driven by a gamepad through
      `gilrs`, and a keyboard path that does the same thing.
- [ ] A badge and a fake progress bar on the covers — the two elements most likely
      to be illegible on a TV from a sofa.
- [ ] A first on-screen keyboard: grid layout, A to type, B to close, X backspace,
      Y shift, shoulder buttons to move the caret.
- [ ] Decide the `eframe` version and the Rust floor: 0.36 requires Rust 1.95 while
      the workspace declares 1.85, so either pin 0.35 or raise the floor
      deliberately.
- [ ] Add the `ui` crate to the workspace and to CI, with whatever system libraries
      the Linux runner needs.

The spike is allowed to be throwaway. What it must produce is answers and a CI job
that builds the crate.

### `grid` — Cover grid with badges and progress (8d)

- [ ] Grid of vertical covers from the `art` cache, with placeholders for missing
      art, drawn from the catalog cache so it works offline.
- [ ] A badge per cover from the `state` registry: not installed, installed, update
      available, failed. **Failed is a visible state**, not a dialog that was
      dismissed and lost — in Big Picture there is no terminal to read an error in.
- [ ] A progress bar along the bottom edge of the cover while installing:
      determinate from the `dl` progress channel, indeterminate during the silent
      install step, with the phase named next to it. No invented percentages.
- [ ] The bar draws over arbitrary artwork, so it needs a solid track behind it
      rather than alpha over the image.
- [ ] The grid stays navigable while something installs in the background, and the
      badge is how state comes back after the UI is closed and reopened.
- [ ] A detail view per game: size, installed version, the per-game log path, and a
      re-verify action once `ver` exists.

### `search` — Search with an on-screen keyboard (5d)

- [ ] Incremental filter over the catalog by title, tolerant of accents and case.
- [ ] The on-screen keyboard from the spike, finished: hold-to-repeat, a symbol
      layer, and a visible caret.
- [ ] Physical keyboards keep working; both feed the same state.
- [ ] Sorting: last played, recently added, alphabetical.

### `actions` — Install and uninstall actions (5d)

- [ ] Install from the grid: pick language and DLC where `man` exposes them, then
      hand off to `dl` and `inno` with progress landing on the cover.
- [ ] Uninstall from the grid, through `uninst`, with a confirmation step and an
      explicit line saying saves are kept.
- [ ] A queue: a second install starts after the first rather than competing for
      bandwidth.
- [ ] Cancel an install, leaving a resumable or clean state, never a stuck tile.
- [ ] Surface the "Steam is running" case from `compat` in a way a controller can
      act on.

### `feed` — Pre and post launch screens (4d)

Folded in from the previous revision's saves phase: it is the same UI binary in a
different mode, not a second toolkit. A floating in-game HUD stays ruled out — it
would need a custom Wayland client using `wlr-layer-shell`, a project of its own.

- [ ] A brief fullscreen window **before** the game, while `ludusavi restore` runs.
- [ ] A brief fullscreen window **after** the game exits, while `ludusavi backup`
      runs.
- [ ] Nothing at all during play.
- [ ] It must never block the launch if the UI fails to start: the wrapper plays the
      game anyway.

## Milestone M3 — Browse and install from the sofa

From a controller alone: browse the library as covers, search for a title, install
it while watching progress on its cover, play it, and uninstall it.

## Risks

- **Legibility on a TV.** Badges and a thin progress bar are exactly what a sofa
  distance punishes. That is what the spike is for.
- **Input focus under gamescope.** If gamescope or Steam's overlay eats controller
  input, the whole phase is in trouble; the spike finds that out in September.
- **Doing the UI twice.** `feed` and the grid must stay one binary and one input
  layer, or the second one will rot.
